# Single source of truth for the CAN messages this system cares about.
# Consumed by tools/gen_dbc.py to emit main/can/dbc/dbc_generated.{c,h}.
#
# Columns (whitespace separated):  NAME  BUS  ROLE
#   BUS  = 0 (chassis / party) or 1 (vehicle) -- the physical bus the frame
#          rides on, i.e. which MCP251xFD instance must accept it.
#   ROLE = decode : firmware decodes this message's signals on-device (full
#                   signal table emitted -- costs flash) AND accepts it in the
#                   HW RX filter for its bus.
#          filter : firmware does NOT decode it; it only opens a HW RX filter
#                   slot so the frame reaches the DashPilot app over BLE. No
#                   signal table is emitted (no flash cost beyond one filter).
#
# Every NAME must exist in dbc/bus_1_tesla_vehicle.dbc.
# Keep decode entries tight: every decoded message costs flash. The per-bus
# filter set (decode + filter, de-duplicated) must stay <= 32 (MCP filter slots).
#
# The `filter` set mirrors what the DashPilot bridge mapper reads per bus
# (dashpilot/bridge/car/cars/tesla.h, TeslaDashKitMapper). With these accepted
# in hardware the app no longer needs to push a CAN filter over BLE.
